# Make the hero clip with code

[Back to the README](../README.md) · [Español](#en-español)

The sample video in [`media/`](../media) was not filmed or generated by an AI video model. It was drawn
frame by frame by [`film/explainer.html`](../film/explainer.html), a single HTML file with a canvas
and about 700 lines of plain JavaScript, and encoded (with a soundtrack made in code) by [`scripts/render_film.py`](../scripts/render_film.py).
You can watch the same film live in a browser, change it and render your own.

## Watch it live

Open `film/explainer.html` in a browser. Like the hero it explains, it starts still and only plays when
you press **Play film**. The film is one 16-second cut in three shapes: add `format=tall` for the vertical
1080 × 1920 one, `format=wide` for 1920 × 1080 (the default is the 1080 × 1080 square), `format=clip` for the
example's own video, `lang=es` for Spanish and `t=12.5` to jump to a moment, joined with `&` after a `?`:
for example `film/explainer.html?format=tall&lang=es&t=12.5`. The links under the player switch the format or the
language and keep the other choice. A text version of the cut you are watching sits under the player.

## How it stays in step with the kit

The film shows an illustration of the page `build_hero.py` writes, and its words and colours come from
the kit itself. [`scripts/film_data.py`](../scripts/film_data.py) builds real pages from
`examples/hero.json` and `examples/hero.es.json`, reads the button and status labels back out of
them, takes the colours from `templates/hero.html` and each language's poster from the path its example names
(`examples/poster.svg`, `examples/poster-es.svg`), and stores
the result in the `kit-data` block of the film, along with the size of the example's clip in `docs/` (the
kilobytes the film opens on). The unit tests fail if that block is stale, so after you change a label, a
colour, the poster, an example config or that clip, run:

```sh
python3 scripts/film_data.py --write
python3 -m unittest discover -s tests
```

That keeps the words, colours and posters in step. The layout and the states the film draws are its own
code, so after a change to `templates/hero.html`, watch the film again and check that every state it shows
is still one the page reaches.

The film also brings the poster to life. `examples/poster.svg` is drawn in layers, groups with
`class="layer"` and the ids `sky`, `aurora`, `lake`, `mirror`, `front` and `label`, and the film animates
them: the aurora waves and brightens, its reflection ripples, the stars twinkle and the cabin's lamp
flickers. That motion is written for this picture. Besides the layers it uses a few hooks, and skips any it
cannot find: the shoreline (the top of the `rect` in `<clipPath id="water-clip">`), the lit window
(`class="win"`) and the cabin's outline (`<path class="cabin">`), and the stars (circles in `#sky`). A
poster without the layers is shown still, in the film and in the clip, with its own text. For a new
picture, keep the ids and change `scene()` to move what it shows.

## Render it

Rendering needs two tools the page builder doesn't: Playwright for Python with a Chromium browser, and
FFmpeg. They are optional; install them only if you want to make videos. A virtual environment keeps
Playwright out of your system Python (which many systems refuse to change). The commands are for a macOS
or Linux shell:

```sh
python3 -m venv .venv                     # Debian/Ubuntu: sudo apt install python3-venv first if ensurepip is missing
. .venv/bin/activate                      # Windows: .venv\Scripts\activate, then python for python3 and mkdir output
python3 -m pip install playwright
python3 -m playwright install chromium    # Linux: add --with-deps if Chromium won't start
# FFmpeg: https://ffmpeg.org/download.html, or your package manager (brew install ffmpeg, apt install ffmpeg)

mkdir -p output
python3 scripts/render_film.py --format square --lang en --output output/hero-demo.mp4
python3 scripts/render_film.py --format tall --lang en --output output/hero-demo-9x16.mp4
python3 scripts/render_film.py --format wide --lang es --output output/hero-demo-16x9-es.mp4
python3 scripts/render_film.py --format wide --still 12.5 --output output/still.png
python3 scripts/render_film.py --format clip --output output/lantern-lake.mp4
```

Each frame is drawn for an exact time (frame ÷ 30 s), screenshotted and piped to FFmpeg as H.264, so the
same inputs give the same film every time. The 16-second square cut takes about a minute on a laptop.
Every cut of the film has a soundtrack made with code: `scripts/score_film.py` (standard library only) synthesises hits, whooshes,
ticks and a low pad from the cues the film lists in `KCUES`, and `render_film.py` adds it to the MP4 (`--silent`
leaves it out). The clip is silent. Run the render commands in the shell where you activated `.venv`. Exit codes: `0` done,
`2` bad input or failed render, `3` Playwright or FFmpeg missing, or Chromium won't start. If you already
have Chrome or Chromium, `--chromium /path/to/chrome` (or `HERO_CHROMIUM=/path/to/chrome`) skips the Playwright
download.

`--format clip` is the example's own video: 10 seconds at 1080 × 1080 that start and end on the
poster's picture, so the switch from poster to video is seamless. `output/lantern-lake.mp4` is the path
the example config names, so the page built from `examples/hero.json` (or `hero.es.json`; the clip has no
words) plays it as soon as it sits beside the page. A ready copy is in `docs/lantern-lake.mp4`. For a clip of your own poster, add `--poster YOUR.svg`: see [Prepare your video](prepare-your-video.md#no-video-yet-make-one-from-your-poster). To put any render in your own hero, copy the MP4 beside
your page, point `video` at it, and check it with `python3 scripts/inspect_media.py output/lantern-lake.mp4`.

| Cut | Size | Length | Beats |
| --- | --- | --- | --- |
| `--format square` | 1080 × 1080, 30 fps | 16 s | a kinetic-type trailer, with sound: what most heroes do (`<video autoplay muted loop>`, and the kilobytes it fetches unasked) · autoplay is rude · make your hero wait · the whole page, and the press on Play: the poster wakes and fills the frame · it moves · text first · 0 B until Play · scroll away, paused · reduced motion starts still (and silent) · a missing file: the page stays usable · one JSON file and one command · the end card over the living scene |
| `--format tall` | 1080 × 1920, 30 fps | 16 s | the same cut for phones: the page is drawn stacked, with the picture under the words, and the scene fills the whole height |
| `--format wide` | 1920 × 1080, 30 fps | 16 s | the same cut for 16:9: the page is drawn wider and the scene fills the whole width |
| `--format clip` | 1080 × 1080, 30 fps | 10 s | the example's own video: the poster brought to life, no words |

## Change it

Everything is in `film/explainer.html`:

- **Shots**: `KSHOTS` (when each shot starts), `KSHOT` (one drawing function per shot), `KPRESS` (the moment of the press on Play), `KTERM` (the terminal lines) and `KCUES` (the soundtrack's cues).
- **Words**: `KW` (the trailer's words), `OPENING` (the text version's line for the press), `END` (the end card's line and call to action) and `ILLU` (the "Illustration" caption), each in English and Spanish. The page's own words, the button labels and the kilobytes in the first shot come from `kit-data`.
- **Look**: colours `KI`, `KC`, `KH` and `KA`; `kword()` and `kdrop()` for the big words; `BOX` (where the words sit in each shape), `PAGE` and `kpage()` (the drawing of the built page: split for square and wide, stacked for tall), `kplay()` (the Play button) and `FULL` (the scene at full frame).
- **The example's video**: `scene()` and `auroraFrame()` animate the poster's layers; `motion()` makes the movement start and end on the poster itself.

Keep it honest: the film is labelled as an illustration, and every state it shows is one the real page
reaches. Keep frames and test renders in `output/` (ignored by Git).

## En español

La película de muestra está dibujada con código por `film/explainer.html` y se codifica con
`scripts/render_film.py`. Ábrela en el navegador (empieza quieta; pulsa **Play film**) y añade
`?lang=es` para verla en español, y `&format=tall` o `&format=wide` para el corte vertical (9:16) o el ancho (16:9). Es un tráiler de 16 s de tipografía en movimiento, con una banda sonora hecha con código (`scripts/score_film.py`; `--silent` la quita). Debajo del
reproductor hay una versión en texto. Para renderizarla necesitas Playwright para Python con Chromium y
FFmpeg (opcionales). Los comandos son para una terminal de macOS o Linux:

```sh
python3 -m venv .venv && . .venv/bin/activate
python3 -m pip install playwright && python3 -m playwright install chromium
# FFmpeg: https://ffmpeg.org/download.html, o tu gestor de paquetes (brew install ffmpeg, apt install ffmpeg)
mkdir -p output
python3 scripts/render_film.py --format square --lang es --output output/hero-demo-es.mp4
python3 scripts/render_film.py --format tall --lang es --output output/hero-demo-9x16-es.mp4
python3 scripts/render_film.py --format clip --output output/lantern-lake.mp4
```

El último comando genera el video del propio ejemplo: la aurora del cartel cobra vida durante 10 s y
termina en el mismo cartel. Ponlo junto a `output/hero-es.html` (o `output/hero.html`) y pulsa Reproducir.

Los textos y colores salen del propio kit mediante `scripts/film_data.py`; si cambias una etiqueta, un
color, el cartel, un ejemplo o el clip de `docs/`, ejecuta `python3 scripts/film_data.py --write`
y las pruebas. La película anima las capas del cartel (`sky`, `aurora`, `lake`, `mirror`, `front` y
`label`) con un movimiento escrito para este dibujo: además usa la orilla (el `rect` de
`<clipPath id="water-clip">`), la ventana iluminada (`class="win"`), el contorno de la cabaña
(`<path class="cabin">`) y las estrellas de `#sky`, y omite lo que no encuentra. Un cartel sin esas capas se
muestra quieto, en la película y en el clip, con su propio texto.
